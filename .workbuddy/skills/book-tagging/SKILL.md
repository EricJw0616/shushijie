# 图书打标签工序（book-tagging）

## 0. 一句话原则

**能读的绝不猜；要猜的必须带证据；带证据的必须能验收。**
每条标签 = `书 + 列 + 锚点 + 判定`，四样缺一不可。

---

## 1. 三层，别混

| 层 | 数量 | 回答什么 | 谁来做 |
|---|---|---|---|
| 形态层 | 20 列（14 形态 + 6 专名） | 书里有哪些可结构化的东西 | 程序为主 |
| 元数据层 | 37 个原子字段 | 这本书的书目身份 | 版权页直读为主 |
| 理解层 | 9 个 | 这本书在说什么、怎么用 | 模型为主 |

分类（P1–P12）**不参与路由**，只在展示层由通过的列派生。

## 标签口径（唯一口径，对外一律用这个；2026-11-17 拍板）

```
73 = 20 形态/专名 + 37 元数据 + 9 理解 + 7 营销
```

| 层 | 数量 | 明细 |
|---|---|---|
| 形态 + 专名 | **20** | 形态 14（定义/枚举/规则/凡式/情节/篇目/引书/曲牌科介/作品/释义/训释/地形/条目/物种条目）+ 专名 6（地名/机构/器物/动物/植物/人物） |
| 元数据 | **37** | 书目识别 8 + 责任者 8 + 出版规格 14 + 分类主题 2 + 营销描述 5 |
| 理解 | **9** | 金句/议题/章节摘要/论点/人物关系/难度/读者对象/核心概念/关键事实 |
| 营销 | **7** | 场景/时令/地域/事件/竞品/一句话卖点/短文案金句卡 |

### 生成方式三分类（比按层分更重要）

| 类 | 数量 | 规则 |
|---|---:|---|
| **A 提取** | **53** | 原文有就抽，没有就空。**不许模型补。** = 形态 20 + 元数据 33（书目识别/责任者/出版规格/分类主题 + 作者简介） |
| **B 理解** | **18** | 书里有依据、但没有现成句子，需要归纳；没依据也空。= 理解 9 + 内容简介/卖点/推荐语 + 场景/时令/地域/事件/一句话卖点/短文案 |
| **C 外部** | **2** | 书里根本没有，靠外部来源。= 获奖记录（公开记录）、竞品（本库按中图法/主题推导） |

53 + 18 + 2 = 73。

> **判据是「原文有没有」，不是「用不用模型」。** 情节/规则/释义也要调模型，但仍是 A 提取。
> 渠道、作者资源需要出版社内部提供，**不在标签体系内**（2026-11-17 踢出）。

计数规则（避免再出现 15 / 64 / 68 / 75 这些旧数）：
- 「名物」已拆成专名，不再单列；
- 「人物」2026-11-17 起进标签；「机构」本来就在专名里，不是新增；
- 元数据 37：加 装帧/语种/原作名/册数，减 读者对象（挪到理解层）；
- 营销 7：加 一句话卖点/短文案金句卡，减 奖项（与获奖记录重复）、减 渠道/作者资源（出版社内部数据）；
- 元数据 37 里有 5 个只做档案展示（责编/校对/美编/插图/印刷厂），仍计入 37；
- **去重原则：同一字段只在一层计一次。**

当前实现进度（2026-11-17）：

| 层 | 目标 | 已实现 |
|---|---|---|
| 形态 | 14 | 14（名物已下线） |
| 专名 | 6 | 6（模型 + 词表 + GBIF；人物按判定适用才抽） |
| 元数据 | 37 | 19（版权页可读的字段） |

### 专名按书型的要求（config/entity_requirements.json）

**专名不是每本都要 6 类。** 每类书只要求其中 2–4 类，规则表在 `platform/config/entity_requirements.json`，
一键审计 `python3 platform/engine/entity_audit.py`（报告落 `platform/entity_audit.json`）。

| 类型 | 必备 | 可选 | 不需要（出现即噪音） |
|---|---|---|---|
| P1 规范型 | 机构 | 地名 | 人物·动植物·器物·事件 |
| P2 知识型 | 机构·器物 | 人物·地名·科属 | 植物·动物·事件 |
| P3 论说型 | 机构·人物 | 地名·器物 | 动植物·事件 |
| P4 叙事型 / P5 戏曲型 | 人物 | 地名·器物 | 机构·动植物·事件 |
| P6 散文型 | 人物 | 地名·器物 | 动植物·事件·组织 |
| P7 韵文集型 | 人物·地名 | 植物·动物·器物 | 机构·事件 |
| P8 条目型 | 地名·动植物·器物 | 人物·科属 | 机构·事件 |
| P9 选集笺注型 | 人物·地名 | 机构·器物 | 动植物·事件 |
| P10 笔记志书型 | 地名·人物·器物 | 机构·动植物·科属 | 事件 |
| P11 图鉴型 | 植物·动物·科属·地名 | 器物 | 人物·机构·事件 |
| P12 纪事型 | 人物·组织·事件·地名 | 机构 | 植物·动物 |

- **必备抽不到才是缺陷**；P11 没有人物是正常，P12 没有组织是缺陷。
- **不是「必备就必须有值」**，而是「必须抽过」：抽了为空要人确认这本是不是真没有。
- **不需要的抽到是噪音**：图鉴里几百个分布地名不该进索引。
- 组织、事件两个抽取器**尚未实现**，审计会标「未做」。

## 2. 形态层：14 列 + 6 类专名，三档，别弄错

| 档 | 列 | 过模型吗 | 怎么验证 |
|---|---|---|---|
| **自证** | 篇目、引书、物种条目 | **不过** | 程序规则：篇目认“第X回/章/卷”；引书认《书名》并排除自指与篇名号；物种条目走版面切分 |
| **半自证** | 定义、枚举、凡式、曲牌科介、条目、训释、地形 | **少量**：程序先筛，抽样校准；整列精度不足时才上模型 | 每列抽 100 条盲标算 precision |
| **语义** | 规则、情节、作品、释义 | **必须**，且判定在抽取之前 | 判定 + 抽检 |
| **专名** | 地名、机构、器物、动物、植物、人物 | 模型抽 + 词表判类；动植物的学名走 GBIF | 逐字回查 + 词典/GBIF 确认 |

### 为什么引书也要验证

实测：B58《小王子》引书 9 条，第 1 条是《小王子》自己；B60《河北廉洁故事》13 条里有 1 条是本书名。
误报率约 10%，修法是一条规则（书名 == 本书书名则跳过），**不需要模型**。

### 为什么规则类必须过模型

实测：B60 的“规则”22 条全是故事台词（“千万”“必须”出现在对白里），
且 22 条全部能在原文逐字查到（91%）——**原文比对对规则抽取是恒真的，挡不住任何误报**。
只有语义判定能分开“在立规矩”和“在转述规矩”。

### 每条候选的判定问句（只问这个）

> 这一段原文里，是否真的存在这张卡所说的东西？

不要问“这张卡好不好”，那是人写的活。

## 3. 元数据层：37 个原子字段

| 组 | 字段 | 来源 |
|---|---|---|
| 书目识别（8） | 正题名、副题名、并列题名、原作名、丛书名、卷次、版次、印次 | 版权页 CIP |
| 责任者（8） | 著者、其他著者、编委会、译者、绘者/插图、责任编辑、责任校对、美术/封面设计 | 版权页 CIP |
| 出版规格（14） | 出版社、出版地、出版年月、ISBN、CIP 核字号、开本、装帧、页数、印张、字数、定价、语种、册数、印刷厂 | 版权页 + PDF 实测 |
| 分类主题（2） | 中图法分类号、主题词 | CIP（读者对象在理解层，不在这里） |
| 营销描述（5） | 内容简介、卖点、作者简介、获奖记录、推荐语 | **模型生成** |

- 32 个进标签体系；5 个只做档案展示：责任编辑、责任校对、美术/封面设计、插图、印刷厂。
- **有 CIP 的书，元数据 0 次模型**；没有的 1–2 次且全部标“待核”。
- 中图法优先级：**版权页 CIP ＞ 人工改判 ＞ 规则建议**。
  例：B60 版权页写着 `D630.9-49`，规则建议只到 `D 政治、法律`。

### 硬校验

1. **ISBN 校验位**：加权 1/3 求和，校验位必须对得上，错一位立刻发现。
2. **CIP 三方比对**：版权页 / 封面 / 文件名，书名或作者不一致 → 标“待核”。
3. **页数**：与 PDF 实际页数比对。
4. **字数**：CIP 的字数是版面估算（B60 标 250,000，实测汉字 124,584），**只能当量级参考，不能当校验值**。

## 4. 理解层：9 个

| 标签 | 粒度 | 输出 | 校验 |
|---|---|---|---|
| 金句 | 句 | 段号 + 原句 | **逐字回查，100% 通过才算** |
| 议题 | 段/篇 | 议题名 + 证据句锚点 | 无锚点即丢弃 |
| 章节摘要 | 篇 | 1–3 句 + 覆盖段范围 | 人工判“是否只用了原文信息” |
| 论点/主张 | 段 | 主张 + 锚点 | 同议题 |
| 人物关系 | 书 | 三元组 + 证据锚点 | 同议题 |
| 难度分级 | 书 | 等级 + 依据 | 抽检 |
| 读者对象 | **书** | 人群 + 依据 | 抽检 |
| 核心概念/术语 | 书 | 术语 + 定义 + 首现段锚点 | 同议题 |
| 关键事实与数据 | 段 | 事实/数值 + 锚点 | 同议题 |

理解层不参与“能不能入库”，只决定“多出什么”。模型全挂，平台照样交付形态层。

## 5. 工序（一本书从进来到落库）

```
1 结构层   切段、目录、页码                      0 模型
2 元数据   解析 CIP；无 CIP 则标“待核”            0–1 模型（只在要生成简介时）
3 判定层   一次调用，逐列输出 适用/不适用/不确定 + 理由 + 证据段   1 模型
4 抽取层   只跑判定为“适用”的列                   0 模型
5 校验层   自证列程序校验；语义列批量核对（每 20 条一批）  2–5 模型
6 理解层   金句 / 议题 / 章节摘要，逐条带锚点       2–6 模型
7 营销层   7 项草稿 + 原文证据，状态 needs_review   2 模型
8 落库     书 + 列 + 锚点 + 判定 + 来源 + 时效
```

一键跑齐：`python3 platform/engine/tag_all.py <code>`，顺序是
cip → clc → judge → cards → entities → quotes → themes → summaries → marketing。
每一步单独 try，失败记账不阻断。

**三条硬规则（2026-11-17 定）**

1. **修复必须通用**：任何修法都写进流水线，不许针对某一本单独打补丁。
2. **所有标签都要跑**：`tag_all` 覆盖全部已实现层，不做“这本先跳过”。
3. **没有就是没有**：源里没有就留空（not_found/空集），不编、不补、不拿别处数据代填。

合计约 **3–10 次模型调用/本**；有版权页的书取下限。

**失败降级**：判定失败 → 标“未判定”，只跑自证列，书照常可搜可读，不阻塞入库。

## 6. 判定层输出 schema（固定，不许自由文本）

```json
{
  "规则":   {"适用": false, "置信": 0.9,  "理由": "叙事为主，规范句为人物台词", "证据段": 12},
  "引书":   {"适用": true,  "置信": 0.98, "理由": "出现《畿辅通志》《清史稿》等 13 处", "证据段": 30},
  "情节":   {"适用": true,  "置信": 0.7,  "理由": "按章分节，每章一个完整故事", "证据段": 1},
  "不确定": ["名物"]
}
```

三态：`适用` / `不适用` / `不确定`。只有“适用”进抽取；“不确定”进候选池。
**模型自报置信必须用验证集做分箱校准后再定阈值**，不能直接用 0.9 当 0.9。

## 7. 提示词模板

### 7.1 逐列判定

```
你是图书内容质检员。判断下面这本书是否包含以下各类内容。
对每一类回答：有用 / 没用 / 不确定，并给出理由和证据段号。
规则：
1. 只根据给出的段落判断，不得推测。
2. 证据段号必须来自下面编号的段落。
3. 拿不准就答“不确定”，不要猜。
4. 输出 JSON。

类别：规则（在立规矩，不是角色说的话）、引书（引用了别的书）、情节（有事件推进）……
【段 1】……
【段 2】……
```

### 7.2 金句

```
你是出版社编辑。从下面段落里挑出可以独立引用的句子。
规则：
1. 只能整句摘抄，不得改写、不得拼接、不得补标点。
2. 只挑脱离上下文仍成立、且能代表本书的句子。
3. 每段最多 1 句；没有合适的就跳过，不要凑数。
4. 输出 JSON：{"items":[{"seg":段号,"quote":"原句"}]}
```

关键在第 1 条（逐字约束）和第 3 条（允许说“没有”），否则模型一定凑满。

### 7.3 议题

```
判断这一段能否对上下列议题之一。可以一个都对不上。
必须同时给出证据句（原文逐字）和段号；给不出证据就不要选。
输出：{"议题":"...","seg":段号,"quote":"...","理由":"..."}
```

## 8. 验收（不达标不许自动交付）

1. **按列抽，不按书抽**：每列抽 100 条盲标，算 precision（95% CI 约 ±6%）。
2. 三条线：≥0.90 自动交付；0.70–0.90 只进候选；<0.70 停用该列。
3. **类型判定的考试**：62 本有真实类型的书做闭卷考，top-1 ≥ 85%、top-2 ≥ 95% 才允许自动落库。
   达不到就降级为“必须人工确认”。
4. 金句单列：逐字回查通过率必须 **100%**，一条不过整批不可信。

---

## 9. 动态标签与热点匹配

静态标签（上述三层）之外，热点标签**不预设**，按需生成：

```
热点文本 → 解析词 → 召回（标签 + 原文）→ 候选书 → 定向抽取 → 临时标签（带热点 ID / 到期日）
```

- 标签表必须有三个字段：**来源**（入库/热点/人工）、**时效**（永久/临时）、**关联**（热点 ID）。
- 没有这三字段，动态标签会污染静态标签。
- 现有实现：`store.hotspot_match()` + `POST /api/hotspot/match`，应用中心「热点匹配」页。

---

## 10. 加一列的门槛（防止空列）

1. 先扫语料：这一列在现有书里出现几次？**有书支撑才加**。
2. 加完重算能力组合的等价类：**类型数量是算出来的，不是拍出来的**。
3. 同步清单：`capabilities.json`、`cards.py` 的 DEFAULT_PLAN、后台矩阵、本文档。

实测（62 本）：表格 1、年表 0、度量衡 0、坐标 1、图注 0、校勘 2、评点 2、注释 26（多为现代脚注）。
**目前只值得加“脚注”一列。**

---

## 11. 禁止事项

1. **不许全跑**：B56 全跑 102 条 / 15 秒，含“凡士林”“功能性子宫”。
2. **不许用形态探测器做路由**：B60 规则 22 条全是台词。
3. **不许让模型自建分类**：类目膨胀后抽取器接不住，跨书不可比。
4. **不许把“逐字校验”当误报防线**：它对规则抽取恒真（实测 91% 放行）。
5. **不许把定位器当资产报**：三级（可直接用/需人筛/仅定位器）必须分开说。
6. **不许为单本书调阈值**：调了要全库回归。

关键：B60「规则」被判 false，22 条假规则没有产生——判定层起作用了。
遗留：`情节` 抽出来仍是章标题、`名物` 仍有个别短语（“功能性子宫”），**这是列级精度问题，判定层管不了**。

理解层（`platform/engine/understanding.py`）已落地：金句 / 议题 / 章节摘要。

- **行式协议**：不用 JSON。原文全是中文引号，模型不转义会把 JSON 打坏（实测 gpt 类模型 40% 批次失败）。
  改成 `SEG: / QUOTE: / WHY:` + `---` 分隔，解析成功率 100%。
- **逐字校验**：`norm(quote) in norm(段文本)`，12–80 字，丢弃章标题式句子。
  交付的每一句都是校验通过的；**通过率是模型守规矩的比例，不是交付质量**。
- 议题与摘要按全书均匀取样，不能只取前 120 段（否则只看到序言）。

## 专名：五类分开，不再用「名物」

| 列 | 键 | 查询库 | 现状 |
|---|---|---|---|
| 地名 | place | `lexicon/place.jsonl` | **36,026 条**（全国行政区划，含街道/镇） |
| 机构 | org | `lexicon/org.jsonl` | 18 条起，靠语料增长 |
| 器物 | object | `lexicon/object.jsonl` | 5 条起，靠语料增长 |
| 动物 | animal | `lexicon/animal.jsonl` | 1 条起；GBIF 只认学名，中文俗名缺权威源 |
| 植物 | plant | `lexicon/plant.jsonl` | 2 条起；同上 |

流程：`entities.py` 模型按段列名 → 逐字校验 → 排除《书名》/人名 → 词典校正类别 → 落 `out/<code>/entities.jsonl`。

B60 实测（2026-11-11 最新）：**1,580 条 / 1,027 个不重复名**
place 742（词典命中 382）、org 201、object 50、animal 8、plant 26；GBIF 确认 25 条（学名级）。

三条修过的坑：
1. **提示词必须留 OTHER 出口**。原来只给五类，模型被迫把「突厥」塞进动物、「牛皮」塞进植物、
   「篝火」塞进器物。加 OTHER + 明确排除民族/政权/材料/泛称后，突厥进 OTHER、篝火牛皮被丢。
2. **顿号连写要拆**。「丝绵、苎麻」原来当一个名字，整串不在原文里 → 被静默丢弃；
   拆开后 B60 从 214 条涨到 1,580 条。**这不是变多，是原来在丢数据**。
3. **网页标题混入**（巴州区政府新闻网）要过滤；机构后缀（学/监/部/司/局/署）要校正类别。

已知噪声：官名当机构（御史中丞）、材料当植物（丝绸、丝绵）、食物当动物（腊鸭）。
已加三类停用词（官名/材料/食物）。

动植物的可靠校验路径：中文名 → 模型给拉丁学名 → GBIF match（EXACT 才算）。
B60 确认 25 条；B56 图鉴测了 300 个物种名：268 个拿到学名，**83 个 GBIF EXACT**（31%），
例：东北红豆杉→Taxus cuspidata、东北龙胆→Gentiana manschurica、中华卷柏→Selaginella sinensis。

B56 实测：5,999 行（place 4,373 行/354 名、plant 1,554/981、org 68/47、animal 4）。
图鉴的分布区会大量重复（朝鲜 162 次、俄罗斯 150 次），这是正常现象，不是误抽。

繁简归一（`zh.py` + `lexicon/ts_characters.txt`）：古籍输出繁体、词表简体，不归一全对不上。
实测 B02 地名命中 22→55（3%→7%），B03 9→17（6%→12%）。**天花板是现代行政区划表不覆盖历史地名。**

GBIF 三级匹配（2026-11-12）：精确 match → `strict=false` → `species/search` 取接受名（含异名），
并加**属名校验**（返回学名的属名必须与查询一致，否则拒绝）。
B56 图鉴物种确认率 **8% → 98%**（391/400）。
注意：确认 = 学名可在 GBIF 查到且属名一致，**不等于中文俗名与学名一一对应**（同物异名仍可能）。

⚠ 性能坑：GBIF 校验**必须按不重复名 + 线程池**。按行串行调用，981 个名字跑 20 分钟没跑完；
改成 10 线程、每个 4 秒超时后，300 个名 1 分钟内出结果。

## 链路接线（2026-11-12）

- **判定接进抽取**：`pipeline.py` 读 `out/<code>/judge.json`，只跑判定为「适用」的列；
  没有 judge.json 时按类型默认跑。⚠ 首次入库时 judge 还没生成，裁剪只在重跑时生效。
- **五类专名进接口与页面**：`GET /api/book/entities?code=&cat=&limit=`，每类各取前 N；
  概览「书里的专名」按五类展示，点一个跳到原文。`/api/book` 里带 `entity_counts`。
- **鉴权**：`app/.env` 里设 `BOOKDISTILL_USER` / `BOOKDISTILL_PASS` 即启用 HTTP Basic；
  不设则不启用（本地开发）。已验证 401/200。
- **重跑保护**：`pipeline.py` 写 book.json 时保留 `CIP`、`CLC`（含人工改判），不再被整本覆盖。

已知质量缺口：分类阶元（卷柏科/地钱属）被模型归成「机构」；GBIF kingdom 只能改判一部分
（26 个里改判 10 个），其余待补「分类阶元」规则。
