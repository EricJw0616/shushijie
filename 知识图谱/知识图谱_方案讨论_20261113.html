00

结论先行

TL;DR

如果只记五句话，记这五句。

  1. 图谱不是第五个库，是资产上的「关系层」节点直接用已有的知识条目 / 人物 / 实体，边是「带出处的断言」：每条边必须能回到原文锚点。不另建一套数据，图谱可随时重建。
  2. 现在 7 本书、0 本可出图，不是数据不够，是问法错了系统问的是「能不能出人物关系图」。B59 有 40 个人物、46 条知识条目，仍被判「不出图」。应该改问：这本书的关系在哪一层、证据密度够不够。
  3. 按书型出四张图，不做一张万能图纪事型出「人物 · 事件 · 地点」，图鉴型出「物种 · 属性 · 功效」，论说型出「概念 · 论证」，叙事型出「人物 · 意象 · 情节」。图谱模板跟着判型走。
  4. 页面不做全屏毛线球，做三栏工作台左图层、中画布、右证据；入口放在书详情页签、条目详情邻接、主题页。默认按篇/主题聚类，超过 150 个节点就「聚焦 + 展开」，不一次画全。
  5. 先做「可核对」，再做「可生成」GraphRAG 问答、选题雷达、编辑核校、营销物料、开放 API，全都从同一张带证据的图出发；没有证据的边不进图。
一句话图谱的价值不在画得好看，而在每条边都能回到原文。这是出版机构和通用大模型公司做图谱最大的区别，也是我们最该守住的东西。
落地进展 · 2026-11-14平台已在「数据资产」与「应用中心」之间加入独立入口知识图谱（#/kg）。已建七张：B59 国之脊梁、B58 小王子、B60 河北廉洁故事，以及 B56 图鉴、B64 十年非梦、B66 乡土中国、YC 野草；后四本用通用结构图保证每本书都有图，后续再按书型提质。页面已按商用深色图谱重构：不再向客户暴露建图决策，只让客户选择显示什么；系统按书决定能出什么图。

数据来自 platform/out/*/book.json、people.jsonl、entities.jsonl、cards.jsonl。B56 的 13,363 个实体是实体表，不等于图谱节点——真正能进图的，是「可讲述、有关系、有证据」的那部分。

关键发现现有「图谱判定」是一个口径打所有书：对白归属、同场密度、强证据人物——这套标准是为叙事类设计的。拿它判纪事型，会漏掉 40 个人物的关系网；拿它判图鉴型，会得出「没有人物所以不出图」；拿它判论说型，根本无从判起。不是要放宽阈值，是要按书型换判据。

为什么现在不合适直接画图

节点会爆炸

B56 有一万三千多个实体。全画出来既看不清，也没法用。图谱节点应当只收「有关系、值得讲」的实体，其余留作属性或索引。

边没有出处

现有实体表是「出现在哪一段」，不是「和谁是什么关系」。把共现当关系，会得到一张看似丰富、实际不可核对的图。

没有准入标准

只有「可出 / 不出」两档。缺 B 类（模型候选、标黄）和 C 类（只出关系索引）的中间态，导致要么不敢做，要么做出来不敢用。

没有页面承载

应用中心里图谱还是一个待接入卡片。书详情五个页签里也没有它的位置，做出来只能是一个孤立的演示页。

02

定位：图谱是资产上的「关系层」

Positioning

把图谱放在正确的位置，后面所有决策都会变简单：它不拥有数据，只引用数据；它不替代条目，只连接条目；它随时可以重建，所以不怕模型升级。

FIG 01

四层架构：图谱长在资产上，不另起一套

复用优先
读法：构建层是唯一「重」的地方，图谱层只存关系与证据，正文仍留在资产层。节点 ID 直接复用条目 ID / 实体 ID，所以改一条条目，图谱能重算，不会出现两份真相。

可重建（Rebuildable）

图谱是派生资产。模型升级、条目改判、人工合并之后，按书重跑即可，不需要迁移「图谱库」。

可追溯（Traceable）

每条边存 anchor_id 与引文。点开边就能回到原文段，这是后面所有应用的地基。

可分级（Graded）

A 已校验 / B 模型高置信 / C 候选。页面默认只画 A+B；C 进候选池，不进主图。

可裁剪（Scoped）

按书、按篇、按主题、按实体类型取子图。接口永远返回「这一屏要的图」，不返回全库。

03

四类书，四张图谱

Four templates

书型决定「关系长什么样」。同一套节点/边模型，四套模板、四种首屏问题、四种验收口径。不要试图做一张能装下所有书的图。

FIG 02

判型 → 模板：四类书对应四种关系形态

按证据形态分，不按中图法分
判型标准：不看中图法，看「关系证据的形态」——有人物同场场景 → 纪事；有分类/属性字段 → 图鉴；有论证与定义 → 论说；有意象重复与情节 → 叙事。现有 P1–P12 判型结果可以直接映射，不需要重跑。

图谱准入：从「出 / 不出」改成三级

级别条件页面怎么用例子
A 可直接出关系经过人工确认；每条边有锚点；实体表已核名默认图层，正常颜色，可导出B59 院士师从 / 任职关系
B 出图 + 标黄模型高置信，有锚点但未人工确认默认显示为虚线/浅色，可一键隐藏B56 物种—功效边
C 只出索引关系证据不足，或实体未消歧不出图，出「相关条目」列表 + 共现提示B60 古人引用、泛称人物

这样 B60 不会被硬判成「不出图」，而是「C 类，先出人物—故事索引」；B59 从「强证据人物 0」变成「A 类人物 40，待核名」；B56 从「没有人物」变成「物种图谱，B 类起步」。

04

本体与证据模型

Ontology & provenance

本体不用大而全。七类节点、八类关系，够覆盖平台现有四类书；真正的差异化在「边 = 断言 + 出处 + 置信 + 校验」这个四元组。

FIG 03

七类节点、八类关系，一条边四级证据

本体从简，证据从严
为什么不是「权重」：出版场景里，读者更关心「凭什么这么说」，而不是「相似度 0.87」。所以边带的是类型和证据，不是分数。分数可以留给聚类排序，不写进本体。
本体取舍不做通用百科本体（人物/地点/组织/作品/事件/概念…几十类），也不做知识推理规则（OWL/RDFS）。先做七类节点 + 八类关系 + 三级置信，够用、能核对、能上线；以后按书型扩关系类型，不动核心表。
05

生产流水线

Pipeline

图谱不是「跑一次模型」，是一条有闸门的流水线。每个闸门都能把不合格的边挡在库外，同时留下候选池——这决定了图谱能不能长期维护。

FIG 04

六步流水线：三处闸门，候选池兜底

可增量、可重跑
复用现有资产：候选实体直接用 entities/people/cards 的产物；对齐可先用「同名 + 别名 + 同篇共现」规则，再上向量；证据回查只查它自己的锚点表。不需要新建抽取引擎。

模型负责什么

  • 从原文抽候选关系与关系类型
  • 给候选边找最近的可引用锚点
  • 生成「关系一句话」，供人工判断

人不负责什么

  • 不从零读全书找关系
  • 不手工输锚点、不抄原文
  • 不做全量复核，只做抽样 + 高风险边
06

页面怎么展示

Interface

图谱页的第一目标不是「好看」，是「可核对、可继续读」。所以采用三栏工作台：左边控制图层与范围，中间看结构，右边看条目与证据。任何一次点击，都能落到原文。

FIG 05

图谱工作台：左图层、中画布、右证据

对应可点击原型
交互约定：① 点节点看条目，② 点边看证据，③ 双击进邻域，④ 搜索定位，⑤ 图层可按关系类型关，⑥ 超过 150 节点自动「聚焦 + 展开」，⑦ 任何锚点可回原文，⑧ 导出与质检常驻。对应原型：知识图谱_原型_孙子兵法.html ↗

六种视图，不要一个画布装所有事

FIG 06

同一份图数据，六种读法

按问题选视图，不按数据选视图
视图不是页面：同一张图切换「总览 / 邻域 / 时间线 / 主题」只是换布局与过滤条件，不换数据。这样每个视图都能共用同一套质检与导出。

三个入口，别让用户先找「图谱」

书详情 · 新增「图谱」页签

在现有「概览 / 知识资产 / 标签体系 / 原文 / 操作记录」之后加第六个页签。首屏直接给该书的图谱总览 + 3 个高频问题入口，而不是空白画布。

条目详情 · 「邻接」块

每条知识条目详情页底部加一块「它和谁有关」：3–5 条边，点进图谱页并高亮该节点，形成「条目 ↔ 图」的双向跳转。

主题 / 专题页 · 路径

已有「主题聚合读法」可以直接升级成主题地图：一个主题 → 跨篇节点 → 原文层。适合做导读、研学、课程包。

降级策略证据不足的书不硬画图：C 类只出「相关条目 + 共现提示」列表，页面明确写「这本书的关系证据不足，暂不出图」。宁可少一张图，不要多一张假图。
07

附加能力：同一张图，长出八种能力

Beyond the canvas

图谱本身不是收入，能力才是。下面按「离钱近、依赖少」排序：前四项建议跟着 P0/P1 一起做，后四项等图稳定后再接；其中图谱质检与版本审计是地基，上一节已经写进 P0。

能力解决什么问题依赖阶段怎么衡量
GraphRAG 问答读者/编辑问「钱学森和钱三强是什么关系」，答案沿边走，附 2–3 条原文引用；比纯向量检索更准、更能解释。图谱 + 检索 + 引用接口P1引用可回查率 100%；人工抽检正确率
选题雷达跨书找「同一个实体/主题在哪些书里反复出现」，输出选题包：哪几本书、哪几章、哪几句可引用。跨书实体对齐 + 标签P1–P2编辑采纳的选题数；命中率
编辑核校人物关系矛盾（师从关系反了）、时间线冲突、称谓不一致、同名未合并；把图谱当「一致性检查器」。人物/事件边 + 质检规则P2每本书查出的问题数；误报率
营销物料一键出「人物关系海报」「时间线长图」「金句卡」，素材全部来自原文，带出处，避免版权裸奔。图谱 + 模板 + 导出P2物料生成量；采用率
导读 / 研学按关系生成阅读路径：先读谁、再看谁、哪几段对照读；适合少儿社做课程包、研学手册。图谱 + 篇目锚点P2+课程包交付数
开放 API / 数据集把图谱作为数据产品：按书/主题导出 GEXF / CSV / JSON，或提供带 Key 的查询接口。权限 + 配额 + 审计P2+调用量；付费客户数
图谱质检孤立节点、无证据边、重名未合并、跨书冲突；既是内部工具，也可以作为交付前的验收报告。图谱元数据P0质检通过率；返工率
版本与审计谁改了哪条边、什么时候改的、依据是什么；对机构客户和版权方是硬需求。事件日志P1可追溯率 100%
FIG 07

能力优先级：先做「可核对」，再做「可生成」

价值 × 依赖
排序逻辑：凡是「答案必须能回原文」的能力优先（问答、核校、质检）；凡是「生成新内容」的能力后置（物料、研学、API 商业化）。原因很简单：图谱的护城河是可核对，不是能生成。
08

数据模型与接口

Data & API

沿用现有文件型存储，先不引入图数据库。四张表就够：节点、边、证据、合并；再加上一个版本号。等边数过十万、或者要支持多租户并发，再迁 PostgreSQL / Neo4j。

FIG 08

最小数据模型：节点 / 边 / 证据 / 合并

先文件，后 PG
为什么不用 Neo4j 作为前置条件：当前规模是「7 本书、万级节点、十万级以内边」，邻接查询用内存 + 文件完全够。图的复杂度在「证据与版本」，不在「图数据库」。等跨书对齐与多租户进来再评估。

10

风险与不做清单

Risks & non-goals

把「不做什么」写清楚，比列一堆功能更能保证上线。

五个真实风险

  • 同名/通名消歧：B60 大量「县令、上司」不是具体人，硬合并会造出假人物。
  • 跨书对齐：同一院士在不同书里写法不同，需要人工兜底。
  • 模型幻觉：关系抽取会编「师从」，必须有锚点闸门。
  • 维护成本：每本书重跑后人工确认不能丢，否则没人愿意维护。
  • 版权边界：导出与物料必须带出处，不能把整段原文当「素材」外发。

不做清单

  • 不做通用百科图谱（人物/地点/组织…无限扩）。
  • 不做「全自动、零人工」的图谱。
  • 不把共现当关系，不做无证据的边。
  • 不把全库实体一次画到画布上。
  • 不先上图数据库、不先做图算法（社区发现、中心性）。
  • 不把图谱做成独立产品页，先嵌进书详情与条目详情。
一个判断如果只能做一件事，做「条目详情里的邻接块 + 边证据面板」。它不惊艳，但它是编辑每天会用的入口；全屏图谱是演示用的，邻接块才是工作流里的。
