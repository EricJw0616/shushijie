# 图书档案声明（book_profile）规格 v1.0

> **解决的问题**：现在 `build_db.py` 的 16 个字段、`catalog.json` 的原型判定，都是「跑完才知道」。
> 换一本书就要改代码。本文把「这本书按什么规则处理」从**代码里的常量**改成**跑之前的输入**。
>
> **一句话**：先声明，再跑。声明里没有的东西，流水线不许自己猜。

## 一、这份声明回答三个问题

| 问题 | 谁回答 | 在哪一节 |
|---|---|---|
| 这是什么类型的书？ | 代码测 + 人确认（仅低置信时） | §2 判型 |
| 这本书该产什么？ | 预设表，不许现场发明 | §3 产物清单 |
| 从这本书里抽什么？ | 代码测字段 + 人确认字段名 | §4 抽取规格 |

## 二、判型：三段分工，不是二选一

### 2.1 三个段的边界

**第一段 · 预设（写进 skill，永不改）**

八种原型，以及每种原型对应的产物清单。这是领域知识，不是这本书的知识。

```python
ARCH = {
    'P1': ('规范型',     ['规范型规则卡', '条款索引', '换版差异表']),
    'P2': ('知识型',     ['概念卡', '先修图谱', '术语表', '易错点']),
    'P3': ('论说型',     ['规则卡+边界', '主题卡', '镜像矛盾']),
    'P4': ('叙事型',     ['人物关系图谱', '情节链', '场所索引']),
    'P5': ('戏曲型',     ['人物关系图谱', '出目情节链', '曲牌科介索引']),
    'P6': ('散文型',     ['引书谱', '意象谱', '态度演变曲线']),
    'P7': ('韵文集型',   ['意象谱', '名句索引', '韵律统计']),
    'P8': ('条目型',     ['词条结构化', '交叉引用', '属性表']),
    'P9': ('选集笺注型', ['篇目索引', '注疏分层', '异文对照']),
}
```

**第二段 · 实测（代码跑，重跑必须一致）**

六轴特征全部由正则计数算出，不接受任何模型参与。判定输入是数字，判定输出是「原型 + 置信档 + 依据句」。

实测数据（22 本已验证）：

| 原型 | 本数 | 置信「中」 | 说明 |
|---|---:|---:|---|
| 叙事型 | 10 | 0 | 对白占比极高，判得稳 |
| 散文型 | 5 | **5** | **全部判不准** |
| 韵文集型 | 2 | **2** | **全部判不准** |
| 知识型 | 1 | 1 | 句均长 32.0 但定义仅 0.6，两轴打架 |
| 论说、条目、戏曲、选集 | 4 | 0 | 特征鲜明 |
| 合计 | 22 | 8 | **36%** |

> **这条分布是本文最重要的事实**：判型规则不是「准」或「不准」，是**对 64% 的书准，对 36% 的书必须有人点头**。
> 设计 skill 时如果假装 100% 自动，那 36% 会被静默判错，而且错得毫无提示。

**第三段 · 确认（只在置信「中」时触发）**

触发条件：`置信 == '中'`。

给出的必须是**可判断的信息**，不是让用户凭空选：

```
《背影2019版》判型需要你确认一下：
  代码测到：第一人称 11.2（每千字）、对白 5.2%、句均长 21.4
  最接近的三个原型：
    P6 散文型    — 第一人称高、对白低，符合
    P4 叙事型    — 但对白 5.2% 太低，典型叙事型在 13% 以上
    P3 论说型    — 但规范词仅 1.1，够不上论说
  → 回车选 P6，或输入其他原型代码
```

用户点头后写入 `book_profile.json`，**此后不再询问**。若要改，改声明文件，不靠重跑。

### 2.2 三条硬约束

1. **人只能从九个原型里挑**，不能现场发明第十种。
   允许现场发明 = 每本书变成一次独立设计 = skill 退化成聊天，无法复现。
2. **八种都套不上的书 → 标 `原型: null` + `待开原型: true`**，正常落盘但不产卡，攒够案例再开新原型。
3. **置信「低」不允许进入第三段**。低置信意味着连候选都排不出来，此时正确动作是**停止并报错**，不是请用户猜。

## 三、产物清单：预设 + 覆盖

### 3.1 三档开关

产物清单从原型取默认值，但每一项可被声明覆盖，取值只有三档：

| 值 | 含义 | 谁定 |
|---|---|---|
| `on` | 必做，不做算失败 | 原型预设 |
| `off` | 不做，原因写进声明 | 原型预设 或 人 |
| `probe` | 先跑取样，够条件才做 | 代码实测后自动降级 |

`probe` 这一档是为了解决「同一原型不同结果」的问题。

### 3.2 实测案例：四世同堂三册

同一个原型（P4 叙事型），三册的图谱结果完全不同：

| 分册 | 强证据人物 | 图谱 | 真实原因 |
|---|---:|---|---|
| 上册 | 11 | **是** | ≥6，可达标 |
| 中册 | 0 | 否 | 强证据不足 |
| 下册 | 4 | 否 | 强证据不足 |

所以「人物关系图谱」这一项的默认值必须是 `probe` 而不是 `on`：

```
probe 规则：强证据人物数 ≥ 6 → 自动升 on，否则降 off。
降级不报错，但必须在产物页写明「本册强证据人物 4 人，低于阈值 6，未出图谱」。
```

> **禁止的做法**：三册合并算总账说「这本书 15 个人物能出图」。
> 三册是三个文件、三次独立处理，**合并统计等于把三次失败掩盖成一次成功**。

### 3.3 另一类：明明该有却抽不出来

《牡丹亭》是 P5 戏曲型，产物清单要求「曲牌科介索引」。实测：

- 曲牌原始命中 **230** 处，科介 **857** 处 —— 都有
- 但 `强证据人物数` 仅 **1** 人，`可出关系图谱: false`

原因写得很清楚：「本类书无稳定对白归属或人名形态」。

结论：**戏曲型的两项产物可做（曲牌、科介），人物图谱不可做。** 这说明产物清单不能按原型整包开，必须逐项独立判定。逐项判定的依据就是 `probe` 规则。

## 四、抽取规格：字段名必须随书声明

这是当前最大的硬编码污染源。`build_db.py` 里写死了：

```python
FIELD_ORDER = ["来源", "别名", "俗名", "原植物", "生境", "分布", "采制",
               "性味功效", "主治用法", "用量", "炮制", "贮藏", "化学成分",
               "识别要点", "附方", "附注"]
```

这 16 个字段只对《中国东北药用植物彩色图志》成立。换成《元曲三百首》，字段应该是曲牌、宫调、作者、原文、注释；换成《古文观止》，应该是篇名、作者、原文、注、评。

### 4.1 字段来源：从书里抽，不从代码里猜

正确做法是**反向提取**：扫描全书，找高频的「标签式短块」（如 `【来源】`、`【别名】`，或行首 2–5 字后接冒号），统计出现次数，产出候选字段表。

然后由人确认，写进声明的 `字段清单`。

### 4.2 字段表的四项必填

每个字段必须写清四件事，缺一项就不许进抽取流程：

| 项 | 例 | 为什么必须有 |
|---|---|---|
| `名` | 来源 | 抽取时的锚点 |
| `必填` | false | 决定缺失时是否算失败 |
| `归一化` | 入药部位收敛到父类 | 不做会出几十个碎片节点 |
| `实测完整率` | 94.6% | 让下游知道这一项的可靠性 |

实测完整率必须来自**实际抽取结果**，不是估算。本项目的真实数据：

| 字段 | 完整率 |
|---|---:|
| 分布 | 99.3% |
| 生境 | 99.0% |
| 用量 | 94.6% |
| 性味功效 | 81.0% |
| 别名 | 70.2% |
| 附注 | 27.5% |
| **识别要点** | **1.4%** |
| **炮制** | **1.2%** |
| **化学成分** | **0.2%** |

后三项接近 0，说明**书里其实没有这些字段，是词表里凭空列的**。这种字段必须标 `off` 并从产物里剔除，否则界面会出现大量空格被误读成「抽取失败」。

## 六、这份声明怎么被使用

流水线改为读声明，不再读代码常量：

```
1. 若声明不存在 → 跑「探测」产出候选声明（只测量，不产卡）
2. 若候选声明 置信 == 中 → 向人确认一次，落盘
3. 若候选声明 置信 == 低 → 报错停止
4. 声明齐备 → 逐项检查产物开关，落 on 的做，probe 的先测再定
5. 全程不读任何代码里的书名字段常量
```

**可验证的出口条件**：把声明文件删掉重跑一遍，产出的 md5 必须与上次一致。做不到就说明还有硬编码在暗中起作用。
