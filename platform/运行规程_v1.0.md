# 出版内容平台 · 运行规程 v1.0

> 这一版的核心变化：**从「一次性手工产出」变成「一条命令可重复运行的流水线」**。
> 22 本书实测，268 万汉字，全部跑通。

---

## 一、一条命令

```bash
cd platform/engine
python run.py               # 整库：判型 → 切段 → 稳定层 → 质检 → 导出 → 看板
python run.py 朝花夕拾       # 只重跑一本书
python run.py --check       # 只质检，不改产物
```

产物落盘：

```
platform/
  engine/        六个模块（structure / wash / measure / library / rules / topics / mirrors / export / board）
  cards/         人工确认过的卡片（JSON，进版本库）
  out/<书码>/    每本书的独立目录，可单独更新
  library/       平台调用的汇总库 + catalog + manifest
  书库平台看板.html
```

加一本新书，只有两步：**把 txt 放进 `书库分类/raw/`，跑 `python run.py`**。
不需要为任何一本书写专用脚本——这是这一版最重要的一条。

## 三、这一轮改掉的四个真错误

写下来，因为每一个都会让整批数据的可信度归零。

### 1. 汉字正则写错，把拉丁字母算成汉字

```python
# 错：\u20000 被解析成 \u2000 加字面 0，范围变成「空格～扩展区上限」
re.compile(r'[\u3400-\u4DBF\u4E00-\u9FFF\uF900-\uFAFF\u20000-\u2FA1F]')
# 对：扩展 B 区必须用八位转义
re.compile('[\u3400-\u4DBF\u4E00-\u9FFF\uF900-\uFAFF\U00020000-\U0002FA1F]')
```

后果：`PAGE 12` 里的 6 个字符全被算成汉字，所有字数、所有六轴特征值都偏。
这就是为什么早先《牡丹亭》保留率只有 92.8%——不是丢字，是把页标记当成正文算了。

### 2. 两套行索引，切篇错位

结构探测和清洗各自算一遍行列表，规则略有不同，篇界下标就对不上，
《四世同堂》三册一度显示「0 篇」。
改为：**清洗直接调用结构模块的行函数**，单一数据源，不再二次匹配篇名。

### 3. 人物抽取，正则做不可靠

抽出过「不知」「并且」「满意」「关于」「空气」。
根因是中文对白归属没有形态标记：「长毛笑道」「母亲便说」「孔子曰」混在一起，
而且现代小说写「声音很低的说：『…』」，人名在 160 字开外。

现在改成双证据（百家姓 + 就近窗口对白归属），**但仍然只是候选**。
所以平台的定位写死一句：

> **人物表、关系图谱属半稳定层，必须确认名单后才能出图。**

实测佐证：儒林外史能出 40 人（第三人称、角色名紧贴说话动词）；
朝花夕拾一篇也出不来（第一人称忆述，几乎没有「某某道：『…』」）。
这不是 bug，是体裁差异——平台照实说，不硬凑一张假图谱。

### 4. 引文回查的校验口径写错了

第一版把「条件」「动作」也拿去回查，13 张规则卡全判失败。
这是概念错误：`条件`/`动作` 是白话转写，本来就不该能回查。
唯一需要逐字回查的是 `原文`。

顺带修掉两处我自己凭印象写的引文（「大众的」、「最大的错处」位置），
教训重申：**写引文必须从产物里取，不许从记忆里默**。

## 六、已知的窟窿（别当已解决）

1. **P1 规范型 0 样本**，阈值是从 P3 倒推的，没有实测依据。
2. **诗体与小说分不开**：神曲判成 P4 叙事型，实际是诗体叙事。三册都受影响。
3. **说明文与教材分不开**：四月天建筑卷判 P2 靠的是「句均长 32」这个单信号。
4. **结构探测仍有漏**：唐宋传奇集只切出 2 个单元（卷），实际是几十篇传奇。
5. **判型 n=22 且阈值是倒推的**，不是拟合出来的。所以平台定位是「建议不拦截」，
   跑前 10 本后必须回校阈值。
6. **半稳定层只做了 2 本**，其余 20 本停在 L0。这是排期，不是能力。

## 八、标签库与图书数据库页（v1.1 新增）

### 8.1 六个工序扩成八个

```
python run.py
  → pipeline  判型+切段+稳定层
  → rules     规则卡质检
  → topics    主题卡质检
  → mirrors   易错对照质检
  → export    导出资产库
  → taglib    生成标签库        ← 新增
  → board     生成论证页
  → tagboard  生成标签数据库页   ← 新增
```

产物：

```
library/tags.json        每本书的六层标签（带来源与验证方式）
library/tag_index.json   标签 → 书的倒排索引
library/tag_dict.json    标签词典（每个标签出现在几本书、区分度）
图书标签数据库.html        对外可用的页面，双击即开
```

### 8.2 六层的定义与边界

| 层 | 问什么 | 来源 | 22 本实测 |
|---|---|---|---|
| L5 能力 | 这本书能拿出什么产物 | 实测 | 8 个去重标签 |
| L4 内容 | 书里写了什么 | 抽取 | 315 个（篇名/引用书目/人物/曲牌） |
| L3 类型 | 属于哪一类书 | **判断** | 9 个（原型 P1–P9） |
| L2 语体 | 用什么语言写的 | 实测 | 9 个（文言率/R/D/A/Q/句长） |
| L1 结构 | 怎么编的 | 实测 | 5 个 |
| L0 原文 | 有多少字、完不完整 | 实测 | 1 个（文本完整/基本完整/有缺损） |

### 8.3 三条硬规矩（违反任一，标签就是假的）

**① 来源只有三种，没有第四种。**
`实测`（程序从正文数出来，你能复算）／`抽取`（正则抽出，带锚点可回查）／`判断`（需人定性，标"待确认"）。
**不承认"大模型说的"这一层**——那是最不可靠又最容易被当成事实的一层。

**② 算不出来的标"未做"，不填默认值。**
标签表的公信力全在这条上：宁可缺一格，不能假一格。
内容层抽不出子类时，页面显示「未抽出：人物」并给出原因，不显示空表让人以为"这书没人物"。

**③ 数字是属性，不是标签。**
`100,405 汉字`、`404 段` 这类每本都不同的数字，做成标签会让词典里塞满只属一本书的条目，既不能筛也看不出区别。
实测踩过：词典前 20 行全是「xxx 汉字」。现在字数是属性，标签只放能横向比较的东西。

### 8.4 两条上过当的方法记录（别再试）

**① 左右邻字熵抽主题词 —— 失败。**
熵衡量"这个词左右能接什么字"，虚词最自由，所以熵最高的全是「没有」「然而」「因为」「我们」。
方法刚好选出停用词。**要抽抽象主题词，只能靠人读完再归纳。**

**② 姓氏法 + 对白归属抽人物 —— 半失败。**
把关、应、于、从都当姓，于是「关于」「应当」「后面」「从他」全被标成"强证据人物"。
现在只收「XX先生/太太/小姐/老爷」这类带称谓后缀的，数量少但都是真的。
**要完整人物表，必须先人工给名单。**

### 8.5 页面能做什么

**2026-10-31 改版：由「标签当入口」改为「书架 → 书详情」两级结构。**

改版原因是旧版让人从标签词典进入一本书，与真实使用相反。现在：

- **书架**（首屏）：22 本书卡，每张写明原型 / 体量 / 内容层实体数 / 标签数 / 有无卡片。
  卡上如实分「有卡片」与「仅检索层」两类，不合并成一个数。
- **书详情**：点书进详情，六层标签逐层展开；点带虚下划线的标签，**原文证据就地展开在标签下方**（不是收到层底部，也不是跳页）。
  下半部分是这本书的三类卡片全文（规则卡带边界、主题卡带层与引文、易错对照带甲乙两栏），以及这本书的能力边界。
- **标签词典**：全库视角，只列出现 ≤8 本的标签，书名可点进详情。这是辅助功能，不是主入口。
- **这批标签的边界**：固定写出训练集为空、人物只出带称谓后缀的、内容层不是抽象主题词表、引用书目有偏斜、无书目字段。

三个不能忘的写作规矩：

1. **置信度不能自己推**。`catalog.json` 的 `置信` 是三档（高/中/低），曾用「有依据=高、无依据=低」在页面上凭空二值化，把「中」写成「低」。必须原样引用。
2. **重绘搜索框会让光标跳**。输入时只重绘卡片网格，不重绘输入框本身。
3. **数字从数据算，不 hardcode**。卡片数、有卡书的数、去重标签数全部由 `manifest` 与 `tags` 实测填充。
