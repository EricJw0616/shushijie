# 理解类 4 项：定义与边界（先补规范）

> 规范原文对“核心概念 / 概念与原理 / 技能与规则”写的是“当前版本未单独列出此项”。
> 这份文件先把定义补清楚，再按它抽取；四项都只出草稿，人工确认后才算数。

## 1. 事实与数值（P01-010）

**打什么**：原文直接陈述的一项事实，或一个带上下文的数值/时间/地点/条件/范围。

**必须满足**：
- 事实或数值能在同一段原文里直接找到；
- 单位、时间、条件、范围按原文保留，不改写、不补算；
- 一条只放一项事实/一个数值。

**不算**：
- 只有观点、没有明确陈述的句子；
- 由多处文字拼接、补算、书外知识得到的结论；
- 纯修辞、比喻、假设。

**值的样子**：
```json
{"fact":"...", "value":"...", "unit":"...", "time":"...",
 "condition":"...", "category":"时间|数量|地点|人物|事件|其他",
 "seg":"B60-01-P01", "quote":"逐字原文"}
```

## 2. 技能与规则（P01-012）

**打什么**：原文明确写出的步骤、做法、条件、限制、例外、适用范围。

**必须满足**：
- 原文有明确的“先…再…”“如果…就…”“须/应/不得/除外”等结构；
- 能拆出步骤或条件；拆不出就不打。

**不算**：
- 只是叙述一件事的过程，没有可复用的做法；
- 小说情节、历史叙事、抒情；
- 需要读者自己总结的“潜规则”。

**值的样子**：
```json
{"type":"步骤|规则|限制|例外", "text":"...", "order":1,
 "condition":"...", "seg":"...", "quote":"逐字原文"}
```

**没有明确步骤/规则的书**：返回空数组，标 `not_found`，不硬凑。

## 3. 核心概念（P01-004）

**打什么**：这本书真正支撑内容的关键概念/术语/短语，3–8 个。

**必须满足**：
- 概念是书里出现并**被定义、解释或反复论述**的术语/短语，长度不超过 12 字；
- 能在原文找到定义/解释/支撑句；
- 说明“为什么它是核心”，不能只凭出现一次或词频高。

**不算**：
- 泛词：人生、世界、生活、故事、思想、文化；
- 只出现一次、没有解释的专名；
- 书外概念（书里没提，不能拿常识补）。

**值的样子**：
```json
{"concept":"...", "definition":"书中定义/解释（压缩，不改事实）",
 "why_core":"为什么是核心", "seg":"...", "quote":"逐字原文"}
```

## 4. 概念与原理（P01-011）

**打什么**：书中明确提出的原理、机制、因果关系、规律，3–6 条。

**必须满足**：
- 有“因为…所以…”“…导致…”“…的机制是…”等明确表述；
- 能说清“概念—原理—适用条件”；
- 只能用原文信息，不能补书外理论。

**不算**：
- 只有概念、没有原理；
- 作者的个人感慨、价值判断；
- 需要读者自己推理出的“隐含原理”。

**值的样子**：
```json
{"concept":"...", "principle":"一句话原理",
 "explanation":"书中怎么解释", "condition":"适用条件/范围",
 "seg":"...", "quote":"逐字原文"}
```

## 5. 共同要求

- 每条都带 `seg` + `quote`，引文必须逐字存在；对不上就丢弃；
- 状态一律 `needs_review`，不自动通过；
- 没有就返回空数组，标 `not_found`，不凑数；
- 不做：词性、句法、跨句指代（放弃）；知识点关系 4 项（等应用层）。
