### 理解类 11 项（未做，保留待做）具体指什么

就是这 11 项：核心概念、概念与原理、技能与规则、事实与数值、词性与语法类别、句法结构信息、跨句语用与指代关系、知识点关联关系、关系方向、关系类型、关系闭合性校验。

共同点：不是“抄下来”，是要机器读懂、推理、判断。比如“这段话的核心概念是什么”“这两个概念是什么关系”“这个‘他’指谁”。

这次不做，不是永远不做，是排到后面。代价是：这 11 项交付里会缺；如果客户合同把它们当硬指标，要单独评估，不能拿“已经有了”糊弄。

### 缺项怎么处理（按你的要求）

- 有值才显示；没有就不显示；不适用也不显示。
- 不出现“未找到/暂无”占位，不瞎标、不补写。
- 内部仍记“未找到/不适用/待人工”，只进质量报告，用来算覆盖率，不进出口径。
- 大模型只能给“候选 + 原文证据”，没有证据不落。
- 客户合同要显式 null 时，导出加开关，按客户模板来。

详见《拿不到的项清单》。

## 1. 一句话方案

**不要再为这 105 项写死代码，把它当成“标签包”，引擎通用、包可配置。**
一本书进来，跑四步：认书（出版信息）→ 认页（页面结构）→ 认内容（已有的人物/摘要/金句）→ 记账（数据集/版权/营销），最后统一进“标注台账”，人复核后导出交付包。

这样做的好处：今天做这 59 项，明天客户换一份规范，只换标签包，不改代码——这是将来商业化的根。

## 2. 现在能复用什么

| 现有能力 | 位置 | 这次怎么用 |
|---|---|---|
| 版权页解析 | 抽取引擎的 CIP 模块 | 第 1 期直接扩字段，不重写 |
| 版面还原 | `layout.jsonl`（每页每行的文字、坐标、行类型） | 第 2 期判断页面角色的主输入 |
| 篇章切分与目录清洗 | 结构模块 | 第 2 期的正文范围、目录页判断 |
| 人物/地点/机构 | 专名实体 + 人物表 | 跨期 5 项直接映射 |
| 金句/篇摘要 | 理解层产物 | 跨期 2 项直接映射；营销简介复用同一套“带出处生成” |
| 标签“来源/证据”机制 | 每条标签带锚点和原文 | 直接升级成统一的“标注台账” |
| 人工改元数据、确认入库 | 现有接口 | 扩展成复核台，不另起一套 |

**不用重做的**：原文切分、锚点定位、证据回查、任务队列、上传预检。这些是现在系统最值钱的部分。

## 3. 总体架构

```
上传/导入（PDF / DOCX / 出版社元数据）
        │
        ├─[1] 元数据抽取 ──────────→ 出版信息（19 项）
        │     规则优先，大模型只做兜底和候选
        │
        ├─[2] 页面角色识别 ────────→ 页面结构（12 项）
        │     版面坐标 + 文本特征 + 大模型兜底
        │
        ├─[3] 已有内容能力 ────────→ 人物/地点/机构/摘要/金句（5 项）
        │
        └─[4] 记录与生成 ──────────→ 数据集信息/版权/营销草稿（23 项）
              表单 + 规则 + 大模型草稿
        │
        ▼
   统一标注台账 annotations（值 + 出处 + 方法 + 置信 + 状态 + 版本）
        │
        ▼
   复核台（接受 / 修改 / 驳回 / 标为不适用）
        │
        ▼
   交付导出（Excel + JSONL〔本期〕 + 数据集清单 + 校验摘要）
```

关键点：**所有项都写成同一种记录**，不管它是规则抽的、大模型写的、还是人填的。这样复核、统计、导出、审计只做一套。

## 4. 第 1 期：出版信息（19 项）

### 怎么做

输入优先级：**出版社提供的元数据 > 版权页 > 封面/封底/书名页 > 大模型兜底**。
出版社元数据是权威源，机器抽取只做补充和核对——这是商业化时最容易被客户接受的方式。

| 字段 | 从哪来 | 怎么取 | 取不到怎么办 |
|---|---|---|---|
| 书名/作者/出版社/印次/出版时间/版次/字数/定价/CIP 号 | 版权页 | 现有 CIP 解析，扩字段 | 标“未找到”，不猜 |
| 责任编辑 | 版权页“责任编辑：”行 | 正则 + 邻近行 | 标缺失 |
| 副书名 | 书名页/封面“主标题：副标题”或破折号 | 规则切分，大模型兜底 | 标缺失，不硬拆 |
| 装帧形式 | 版权页/封底“精装/平装/线装…” | 关键词 | 标缺失 |
| 页数 | 版权页“208 页 / XII, 208 页” | 正则，保留原文范围 | 不用 PDF 物理页数 |
| 丛书名 | 版权页/书名页“××丛书” | 规则 + 层级 | 标缺失 |
| 作者简介 | 封底/勒口/作者介绍 | 只抽取现成文字，不让 AI 写 | 留空 |
| 翻译相关人员 | 版权页著者串 | 按“译者/译审/校译/编译”拆人+角色 | 保留原串为证据 |
| 开本 | 版权页“880×1230 毫米 1/32” | 拆成“开数”和“成品尺寸”两条 | 标缺失 |
| 书号 | 版权页/封底 | ISBN-10/13 校验 + 统一书号识别 | 标无效，不改号凑数 |
| 分类 | 版权页/编目页 | 中图法代码+名称；补“体系/版本”字段 | 只有代码就只存代码 |

### 能不能达到

**能，确定性最高。** 版权页上基本都印着；现在 4 本书里 2 本有完整版权页，另外 2 本没有，正好验证“取不到就标缺失”的路径。
风险：只有 4 本样书，字段写法不够全；需要 20–30 本不同出版社的书做评测。

### 验收

- 有版权页的书：字段抽取覆盖率 ≥ 90%，人工复核后 100% 可交付。
- 没有版权页的书：必须给出“未找到 + 原因”，不能编。
- 每个值都能点回原文位置。

## 5. 第 2 期：页面结构（12 项）

### 怎么做

**先规则，后大模型，最后必须允许“其他/未分类”。**

每页提取这些特征：
- 页眉页脚：页码位置（居中/外侧）、是否重复 running header；
- 文本特征：行数、行宽、首行缩进、点线（目录）、短行比例；
- 关键词：图书在版编目、责任编辑、目录、前言、序、后记、附录、参考文献、索引、勘误；
- 位置：前 10 页 / 后 10 页 / 中间；
- 页与页的连续性：目录通常多页连续，正文页有稳定页码。

判断顺序：
1. 封面：第 1 个非空页，行少、字大（没有字号也能看行数和居中）；
2. 版权页：出现 CIP/ISBN/印刷信息；
3. 书名页：书名+出版社，位于封面和版权页附近；
4. 目录：出现“目录”且有大量点线/页码；
5. 前言/序/导读：出现“前言/序/导读”，且在正文前；
6. 正文：目录之后、后记之前的主体页；
7. 后记/附录/参考文献/索引/勘误：关键词 + 位置；
8. 其余：标“其他”，不硬塞。

输出：页码区间 + 角色 + 置信度 + 证据（哪一行、哪个特征）。

### 能不能达到

**主要角色能，少数角色有条件。**

- 封面、版权页、书名页、目录、前言、正文、后记、附录、参考文献：**确定性较高**，规则能覆盖大部分。
- 索引、勘误表：**样本太少**，先做“能识别就识别，识别不到标其他”，不承诺覆盖率。
- 标题层级：**只能部分支持**。没有字号信息，只能用“第X章/第X节”编号、目录缩进、行宽来推。要完全做准，需要第 3 期的字号——这是本次范围的一个已知缺口。

### 格式差异

- PDF：有版面坐标，按上面的做法。
- DOCX/TXT：没有“页”，只能按标题和文本顺序判断“前言/目录/正文/后记”，页级角色标“不适用”。这一点要提前和客户说清楚，不能拿 PDF 的承诺套 DOCX。

### 验收

- 主要 8 类角色在 30 本书上的准确率 ≥ 90%，且“其他”页不被强行归类。
- 每个判断都能指出依据（哪一页、哪一行、什么特征）。
- 允许人工拖拽调整页码区间，调整留痕。

## 6. 第 4 期：数据管理 / 版权 / 营销（23 项，仅营销保留）

### 6.1 数据集信息（9 项）

数据集标识、版本、关联资源、结构类型、语言、责任主体、文件构成、内容简介、标注证据位置。

**这些不是“读书”读出来的，是发布/交付时的台账。**
做法：项目发布时生成一条数据集记录，字段来自项目配置 + 文件清单统计；版本号、生成时间、校验摘要一起落库；发布后锁定，改动留痕。
内容简介两条口径要分开：
- 基础包“现成简介”：只抽取版权页/封底已有的简介；
- 营销包“整书概括”：大模型生成，必须带原文依据，人确认。

### 6.2 版权记录（4 项）

权利状态、归属方式、获取方式、许可范围。

**技术不能自动判断，只能做“记录 + 提醒 + 凭证”。**
做法：表单录入 + 上传授权文件 + 状态机（未知/已授权/公有领域/到期）+ 到期提醒；数据集导出时把权利状态一起带出。
这条不要承诺自动化，销售时也要讲清楚：系统保证“有记录、可追溯”，不保证“权利真实有效”。

### 6.3 营销（7 项）

关键词、内容简介、目标读者、适用场景、阅读收获、情绪价值、营销线索。

**能做，但必须是“草稿 + 人定稿”。**
做法：
- 大模型读全书（复用现有金句/摘要的“带出处生成”），每个结论必须挂原文；
- 每条给“草稿/置信/依据”，人点“采纳/改写/驳回”；
- 关键词按现有规范做 5–15 个、排除宽泛词/广告词，两次独立判断；
- 成本控制：按需触发、批量缓存、先用便宜模型，人工只处理低置信。

### 能不能达到

**数据管理：能（流程问题，不是技术问题）。**
**版权：只能记录，不能自动判定。**
**营销：能出可用草稿，但不能承诺“自动正确”，必须人审。**

## 7. 数据模型：一套引擎吃所有标签包

### 标注记录（每项一条）

```
书号 / 标签包ID / 包版本 / 标签ID / 组 / 字段
值（文本/列表/类型化）/ 取值类型
证据：页码、段号、原文片段
方法：规则 / 大模型 / 人工 / 导入
置信度 / 状态：草稿/自动/待复核/已确认/已驳回/不适用
复核人 / 复核时间 / 引擎版本 / 模型版本
```

### 标签包（可配置）

```
包ID、版本、适用范围
组：处理层级、执行方式、门槛、共用规则
标签：编号、名称、定义、边界、取值、证据要求、校验器、提示词
```

这次解析出来的 105 项，本身就是一份标签包；我们已经在做“DOCX 规范 → 机器可读标签包”的转换。**这是商业化时最值钱的一块：客户给一份规范文档，平台就能生成一套可执行的标签包。**

### 存储

现在是文件（每本书 JSONL）。商业化前要加：
- 租户/出版社维度（现在没有）；
- 标注记录的索引（按标签、状态、书查询）；
- 版本与审计（谁改了什么）。

短期可以继续文件存储 + 索引文件，别为了商业化提前上数据库；但接口要按“多租户”设计，别写死单库。

## 8. 复用与商业化

### 可单独卖的能力

1. **标签包引擎**：任何出版社的规范文档 → 可执行标签包 → 自动标注 + 复核 + 导出。
2. **页面角色识别**：不依赖 105 项，任何 PDF 书都能用（目录/前言/正文/附录切分）。
3. **元数据抽取**：任何图书建档、馆配、电商上架。
4. **带出处的生成**：金句/摘要/营销草稿，每条能回原文——这是和“随便调个模型”最大的区别。
5. **交付台账**：数据集版本、覆盖率、复核记录、校验摘要，直接对应数据交付合同。

### 商业化必须提前想的

| 事项 | 现在 | 要做到 |
|---|---|---|
| 多租户 | 单库单用户 | 出版社隔离、权限、审计 |
| 版本 | 包版本有，引擎/模型版本散落 | 每条标注记全三个版本 |
| 计费 | 无 | 按书/按标签/按 token，成本可见 |
| 部署 | 本机 | 私有化（出版社数据敏感）+ SaaS 两种 |
| 合规 | 来源“仅测试/待核验” | 来源资格核验、版权记录、删除机制 |
| 质量承诺 | 无实测 | 每个标签包一套金标准集，按版本公布准确率 |
| 标准声明 | 文档自述非官方 | 对外不宣称“符合国标”，只称“按客户规范执行” |

### 复用的边界

- 页面角色识别复用到新书没问题，但**版式差异大**（古籍、图鉴、教材）要重新调规则；
- 元数据抽取复用到新出版社，**版权页格式**要配置；
- 营销生成复用到新品类，**提示词和禁用词**要按品类调；
- 所以“复用”不是零成本，是“配置 + 小调”，这点要在报价和交付里说清楚。

## 9. 和现在的 P1–P12 有没有冲突

**结论：不冲突，但有三处边界要划清；不划清就会打架。**

P1–P12 是“这本书能出什么内容产物”的类型层（规范/知识/论说/叙事/戏曲/散文/韵集/条目/选集笺注/笔记志书/图鉴/纪事）；这次的 59 项是“出版与交付要填什么”的字段层。两层正交。

三处边界：

1. **人物/地点/机构只能有一份。** 现在 L4 标签里有“人物候选”，新包里也有“人物”。必须共用底层实体表和证据，不能各抽一遍，否则同一本书两个页面数字对不上。
2. **页面角色只读，不改版面。** P11 图鉴靠版面还原抽物种条目；新的页面角色识别也读同一份版面数据，但只输出“这页是什么”，不许回写、不许改页界。顺序：版面还原 → 页面角色 → P11/P12 条目抽取。
3. **按类型设“不适用”。** 不是每类书都有全部 59 项：P4 小说通常没有索引/参考文献/勘误表；P7 韵集没有“章”层级；P8/P10 条目型没有章节；P11 图鉴常没有标准版权页。这些标“不适用”，不算“缺失”。

唯一要动现有代码的地方：把“人物/机构/地点”的底层实体表做成共享，页面角色作为新产物旁路接入；不动判型、不动 P11 的抽取逻辑。

> 注：系统现在实际有 P12 纪事型，不只 P1–P11；规则同样适用。

## 10. 界面怎么摆（本次先不做，后续再议）

先做功能，等能跑通再定界面；下面三个方案留作讨论底稿，不用现在拍。

### 方案 A：都塞进书详情（轻）

书详情加两个页签：**出版档案**、**营销素材**；页面结构放在“标签体系”里。
优点：改动小，现有导航不变。
缺点：没有批次视角，105 项交付检查做不了；书一多就看不出哪本缺什么。

### 方案 B：独立“交付工作台”（重）

新开一个工作台：左边书列表，中间 105 项矩阵（行=标签，列=书，色块=状态），右边证据/操作；顶部覆盖率、待复核、导出。
优点：最像“数据交付”的真实工作，销售演示也好看。
缺点：单本书的日常编辑还是要回书详情，等于两套界面。

### 方案 C：混合（推荐）

- **书详情**负责单本：加“出版档案”“页面结构”“营销素材”三个页签；
- **交付工作台**负责批次：矩阵、待办、导出、验收报告；
- 两边共用同一套标注记录和复核组件。

## 11. 分期、验收、风险

### 分期

| 期 | 内容 | 前置 | 大致体量 |
|---|---|---|---|
| 第 1 期 | 出版信息 19 项 + 复核接口 | 20–30 本样书 | 小 |
| 第 2 期 | 页面结构 12 项 | PDF 版面数据 | 中 |
| 第 4 期（仅营销） | 营销 7 项；数据集 9 + 版权 4 放弃 | — | 小 |

### 每期验收

1. 覆盖率：内部状态统计（有值/未找到/不适用）；交付只输出有值项。
2. 准确率：金标准集上，机器值 vs 人工值。
3. 证据率：有原文出处的比例必须是 100%。
4. 复核效率：单本复核时间。
5. 导出通过：按目标 schema 校验无缺字段、无非法值。

### 风险

- **样书太少**：4 本，且 2 本没版权页；页面角色识别至少 30 本、跨 3 种版式。
- **DOCX/TXT 没有页面**：页级结构只能降级；要提前划清。
- **标题层级缺字号**：第 3 期不做，标题层级只能部分支持。
- **大模型不稳定**：营销草稿必须人审；同书重跑要能对比。
- **来源资格**：现有规则来源多为“待核验/仅测试”，对外不能宣称合规。
- **多租户缺失**：商业化前必须补，否则只能单客户私有化。
