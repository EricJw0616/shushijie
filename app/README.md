# 书世界 · 图书知识库（平台原型）

## 营销资料逐步核对（2026-11-24）

营销资料页检测到来源问题后，提供一个“开始核对”入口，在同一页逐条完成：将原版页或原件文本与完整识别段落对照 → 明确勾选并保存原文核对 → 单独确认营销资料 → 继续下一条。原版页可放大，第二步可展开全部原文引用；同一段原文被多条资料引用时复用已保存的核对记录，每条营销资料仍分别确认。跳过不改变状态，不采用保存为停用；关闭或刷新后可继续，未保存的修改按标签页暂存，确认勾选不会恢复。

PDF 段落要求可读原版和有效页码，TXT、Markdown、Word 段落要求在上传原件中唯一定位到对应文字，两者均核对当前版本。文字无误时只解除当前段的 OCR／文字顺序问题，保留其他段及原有审核；手改文字会保留原段审计备份，引用它的旧衍生成果必须重新生成后才能确认。源文字变化沿用全书来源版本规则，会使同书既有审核结论需要复核。结构归属问题、空白或缺失正文不靠勾选放行，可以跳过或停用。生成营销资料仅基于已有原文更新营销资料，不重解析 PDF。

接口：`GET /api/marketing/source-review` 获取完整核对上下文；`POST /api/marketing/source-review/verify` 保存版本校验后的单段核对；`GET /api/book/source-page` 返回有边长限制的 PDF 物理页 PNG。第二步复用带资料版本校验的 `/api/content-assets/review`，不会自动批准或改变项目。批量确认仍先检查全部选择，存在阻挡时零审核写入。

## 小红书笔记

打开「营销工具 → 小红书笔记」。可以从书库带入书名和正文节选，也可以手填书名、粘贴资料或上传 TXT、Markdown、DOCX、可提取文字的 PDF。资料编辑区最多使用 16,000 字，长文件会提示截取。每批可选 1–20 篇，逐篇显示进度和生成结果，部分失败时仍可编辑或导出已生成的稿件。初稿包含标题、正文、话题标签及在资料中可逐字找到的依据。可手改正文或选中一段定向改写，再复制笔记或导出 Markdown。

网页可上传 1 张封面和最多 5 张参考图，逐张预览或移除。写作使用平台已有的文本模型，视觉分析使用同一服务的视觉模型，百炼可通过 `app/.env` 的 `BOOKDISTILL_XHS_VISION_MODEL` 指定。视觉分析不可用时会显示状态并继续文案。

同页的「原版完整创作」在运行书世界的本机 Mac 上启动按 [ShiyeLab/write-xhs `be05856`](https://github.com/ShiyeLab/write-xhs/tree/be058561f228305a6df8981d205b5dd230a5f08a) 构建的桌面应用。两个工作区各自管理任务和附件，书库选书在网页使用，完整制作在原版按其流程提交资料与商品图或内页照片。

| 项目 | 网页文案 | 原版完整创作 |
| --- | --- | --- |
| 写作 | 基于资料逐篇写 1–20 篇并核对原句，可局部改稿 | 文+图、文案、纯图和自动选向批量，包含热点、方向规划、全文排版和局部改稿 |
| 封面与参考图 | 上传后提取视觉信息，输出配图建议 | 图书实拍和电商头图使用商品图，内文海报使用独立内页照片，另有知识图解和金句海报 |
| 模型 | 平台配置的文本模型和视觉模型 | 火山方舟 Seed 2.1 Pro 负责理解、规划与排版，Seed 2.1 Lite 负责逐篇写作，Seedream 5.0 Pro 负责生图，可选 DeepSeek 和 Kimi 官方写作通道 |
| 交付 | 复制文案、Markdown | Word、Markdown、成图和任务归档 |

原版的云端生成使用应用内配置的火山方舟模型权限，纯图模式的金句海报在本机排版。原版入口使用独立的成果目录 `~/Library/Application Support/BookWorld/Xiaohongshu/成果`。

## 营销资料到营销策划（2026-11-23）

主导航“应用与接口”改为“内容应用”；单书入口统一为“营销资料”，页面标题为“图书营销资料”。每条未停用资料可点“用于营销策划”：

- **已有项目**：选择营销项目，带入该条资料及其当前版本、原文出处和核对状态，进入项目材料选择。重复加入保留原项目决定；此前已标为“不采用”的资料转到“素材与出处”查看。收集本身不改现稿或撤销已有审核。
- **新建项目**：先选择整体方案或渠道内容，再填写主题、受众与目标。仅预选来源图书，不自动填写受众或目标。点击“创建项目并带入资料”后才保存项目，取消不会创建空项目。新建与资料带入在一次写入中完成；失败重试不会重复创建。

资料进入项目时为候选状态，采用与全局核对仍分别处理。未提交表单按来源资料和内容场景分别暂存于当前浏览器标签页，刷新可恢复；链接保留资料来源。原 `#/marketing/<书码>` 路径兼容。本文以下历史记录中的旧名称仅保留追溯。

## 营销策划任务（2026-11-21）

场景项目在页眉和制作步骤中持续标明正在制作的内容。候选素材展示概要、用途和直接选入按钮；选入不等于全局审核，已选待核对素材也可先生成待审初稿。生成后进入对应场景页，预览并明确应用后才修改工作稿。

前端按公众号文章、短视频脚本、小红书笔记、达人讲书和书店活动提供入口；整体策划为独立的辅助入口。多场景项目按场景分别阅读、编辑和复制当前稿，出处在系统内回查。切换只改变视图，不修改任务或稿件；读取的是当前编辑内容，无法可靠拆分时保留完整稿。营销记录可按场景筛选，同一项目可以出现在多个对应场景下。

渠道营销默认交付实际文章或脚本：公众号保留标题、正文和结尾；短视频先确认完整口播，再分别生成图片或视频提示词。复制和导出不附带项目说明、传播假设、材料复用建议或内部编号；编辑过的正文以当前稿为准。可选内容调整建议默认折叠，展开后提供补选素材和修改要求入口；真实引用审核问题仍须处理。旧交付记录保留原文件，重新导出生成新的内容版本。公众号文章下一步复制到公众号编辑器配图排版；系统不代为发布。

跨书共用约束集中在 `marketing_context.py` 和 `video_prompts.py`：区分内容观众、图书读者与购买决策者；正文回应核心问题并服从篇幅；人物身份参考不能证明历史道具或场景；视频提示词只生成画面，完整配音在剪辑时统一加入。初稿可按检查意见改写，视觉提示词不得改写已确认口播。生成结果与审核结论都不能替代编辑判断。

自动审核格式不合格时只重核一次；仍无效则保存失败，保留原稿与历史。私有失败诊断位于 `app/data/project_assists/.diagnostics/`，用于排查实际输入与引文错误，不经项目接口返回。测试覆盖无效引用、版面噪声、角色区分、定向修复、历史恢复与只读下载；真实跨书自检另保存浏览器记录与 PDF 检查结果。


入口：当前 Codex 本地副本 `http://127.0.0.1:8943/#/records/marketing` → 新建营销策划。
沿用项目概览、项目材料、营销稿和交付记录，不新增独立导航。

- **老书新卖点**：选择一本推广书和目标读者，发现有原文依据的故事与观点，形成传播角度。
- **跨书主题营销**：选择至少两本推广书，生成主题安排，并逐本列出本书贡献和自己的材料依据。
- **渠道素材包**：选择推广书及公众号、小红书、短视频、达人讲书或书店活动，逐渠道生成标题、正文／脚本、行动引导和来源。
- **通用营销／新书上市**：保留已有单书和新书资料工作流，旧项目无需迁移。

任务可先保存，开始发现和生成时检查所需信息。三类新任务默认在本次推广图书内发现材料；每本推广书需要自身有效材料，修改推广对象后会提示旧材料不在范围。跨书结果不得串用其他书的依据，渠道结果必须覆盖所选渠道。结果先预览，明确应用后才更新工作稿，再沿原流程核对引用、审核和导出。改任务会使原生成记录失效，历史交付版本保留。

当前是营销工作稿能力，不代表内容已获公开使用授权或传播效果已被验证。原文解析、导读与正文区分仍影响结果质量；热点预测、销售归因及渠道自动发布不在本次实现范围。

验证：新增 `app/tests/test_marketing_tasks.py`，覆盖任务数据持久化、范围、跨书归属、渠道覆盖、旧任务兼容和审核导出。真实模型已在隔离验证中运行三个任务；产物保存在 `.local/marketing-tasks-20261121/`，属于测试草稿，未作为真实采用或发布记录。


一个面向出版机构的内容中台：**数据资产模块先落地「图书库」**——上传一本书 → 分类 / 内容切分 / 知识条目 / 标签 → 自动入库 → 看档案与原文。

这只是平台的第一个功能模块；应用层（智能问答、知识图谱、营销物料、开放 API）通过统一资产接口接入，不在第一版里硬做。

- **C 外部 2**：书里根本没有 —— 获奖记录、竞品

## 知识图谱（2026-11-14 接入 · 深色商用版）

导航在「数据资产」与「应用中心」之间，独立入口：**知识图谱**。

产品口径：

- **每本书都有图**：解析完成后自动追加建图步骤；有专门模板用模板，没有就用通用兜底，保证新书不会因为没有构建器而被挡在图谱外。
- **不在客户端暴露建图决策**：不显示「待建图 / 可出索引 / 数据不足 / 30 条边试跑 / 登记需求」。客户只选择「显示什么」。

## 启动（Windows、macOS、Linux）

需要 Python 3.9 或更新版本。PDF 在服务器端生成，浏览器下载普通 PDF 文件；不依赖 macOS 打印、Chrome、Homebrew 或用户电脑上的中文字体。

首次在本机部署时，在**项目根目录**建立虚拟环境并安装依赖。已有 `.venv` 时不要重复创建，直接用它的 Python 安装依赖。虚拟环境不可从另一台机器或另一种操作系统复制过来使用。

macOS / Linux：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r app/requirements.txt
python3 app/run.py --check
python3 app/run.py --port 8942
```

Windows（PowerShell 或命令提示符）：

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r app\requirements.txt
py -3 app\run.py --check
py -3 app\run.py --port 8942
```

Windows 没有 `py` 命令时，可以把上述 `py -3` 换成已安装的 `python`。浏览器打开 `http://127.0.0.1:8942`。

`app/run.py` 会优先选择项目 `.venv`，并实际生成一份内存中的短 PDF 检查依赖和中文字体；`--check` 只检查，不启动服务，也不写入项目记录。缺少依赖时给出对应解释器的安装命令并退出，不会自动联网安装，也不会覆盖已有环境。

配置好依赖后，也可以使用快捷入口：

```bash
# macOS / Linux
sh app/start.sh 8942
```

```powershell
# Windows
app\start.bat 8942
```

默认只监听 `127.0.0.1`。服务器部署时使用：

```bash
python app/run.py --host 0.0.0.0 --port 8942
```

这里的 `python` 指已经安装的 Python 3.9+；macOS / Linux 也可使用 `python3`，Windows 可使用 `py -3`。日常启动请走 `run.py` 或快捷入口，避免直接运行 `server.py` 绕过项目环境及依赖检查。

商用部署请在反向代理上加登录 / HTTPS；当前版本没有内置账号体系。

### PDF 导出

同一条交付记录可以下载 Markdown 和 A4 PDF。安装 `app/requirements.txt` 即包含 PDF 排版依赖；项目随附 `app/fonts/NotoSansSC-Regular.ttf` 和 `NotoSansSC-Bold.ttf`，字体以 SIL Open Font License 授权，并嵌入导出的 PDF。Windows、Linux 和 macOS 使用相同的排版与字体，不需要另装系统字体。

需要替换字体时，设置 `BOOKDISTILL_PDF_FONT` 为可嵌入的中文 TrueType 字体文件路径，然后运行 `app/run.py --check` 确认。不要仅把字体文件改名为 `.ttf`；检查未通过时会说明缺少的组件或字形。

## 数据与存储

**没有 SQLite。** 业务状态全部是文件：

```
app/data/
  library.json          # 图书索引：书码、作者、来源、状态、时间
  jobs/<id>.json        # 解析任务状态与步骤
  archives/<code>.jsonl # 每本书的操作记录
  trash.json            # 软删除回收站
  uploads/<id>/         # 上传原件（保留可追溯）
  failed/<id>/          # 失败时移出的底本

platform/out/<code>/    # 引擎产物：book.json / segments / cards / outline / people
platform/library/       # 汇总：books.json / catalog.json / tags.json / cards_candidate.jsonl
platform/config/        # capabilities.json（后台能力设置）
```

达人匹配随应用部署 `app/resources/creator_match.jsonl.gz`。接口从应用目录读取该文件。部署包应包含 `app/resources/`。更新达人库时，在有清洗版 Excel 的环境运行 `python app/creator_match_import.py <清洗版Excel路径>`，然后部署生成的数据文件。

达人作品的公开样例随 `app/resources/creator_works.jsonl` 部署，运营补充的作品保存在 `app/data/creator_works.json`，与其他业务数据一同持久化。内容匹配把图书简介与作品资料交给已配置的模型分析，并验证推荐引用能在对应材料中定位。达人账号、昵称和商品类仅用于身份关联和结果展示。

点击「匹配达人」会先核对已收录的作品。图书简介完整且本地没有命中时，系统会按本书的具体主题分别检索公开作品。右侧「自动查作品」可针对已提交的图书或单个达人重新查询。使用百炼模型网关时，可复用已有密钥调用百炼联网搜索增强版，所用密钥需具备该工具权限。也可以在 `app/.env` 或环境变量配置博查搜索密钥 `BOOKDISTILL_WORKS_SEARCH_KEY`，优先使用博查。系统用当前配置的模型从图书内容提取检索词，通过抖音号或已核对的原链接确认作品归属。查找反馈区分联网异常、作品归属待核对和相关内容缺失。内容匹配分由题材衔接、表达方式和证据质量组成。达到 80 分且原链接、作品内容和具体关联齐备时提示可加入备选，由用户确认。

存储层收在 `app/store.py`，以后换 PostgreSQL 只改这一层，API 与前端不动。

## 上传支持

- `.txt` / `.md`：UTF-8 / GB18030 自动识别
- `.docx`：按段落与表格抽文本（依赖 `python-docx`）
- PDF（`.pdf`）优先读取文件自带的文字（依赖 `pdfplumber`）。配置本机页面识别后，可上传扫描版或夹有扫描页的 PDF。系统只尝试识别难以直接读取的页面。
  双页拼版和多栏尽量按阅读顺序整理。识别得到的文字在引用前应对照 PDF 原页核对。版面记录位于 `书库分类/raw/<书名>.layout.jsonl`。

上传时会做最低限度的质检：汉字量、汉字占比、句末标点、平均句长。明显不可用的文本不会灌进库。

### 配置 PDF 页面文字识别

页面文字识别在运行书世界的机器上完成，使用 RapidOCR 和 PDFium。安装依赖后，识别页面不需要联网。

在 Linux 或 macOS 上，从项目根目录运行以下命令。

```bash
python3.11 -m venv .venv-ocr
.venv-ocr/bin/python -m pip install -r platform/engine/requirements-ocr.txt
```

Windows 使用 `py -3.11 -m venv .venv-ocr`，并用 `.venv-ocr\Scripts\python.exe` 安装同一份依赖。
应用自动查找项目根目录的 `.venv-ocr`。识别环境已安装在别处时，启动应用前将 `BOOKDISTILL_OCR_PYTHON` 设为环境内 Python 可执行文件的绝对路径。设 `BOOKDISTILL_PDF_OCR=0` 可关闭此功能。

预检抽样读取文件自带的文字。页面识别在点「开始入库」后进行，进度见任务记录。「查看解析情况」里的「页面检查」列出未读到文字、识别或阅读顺序待核对的页面，并提供原 PDF 页码。空白页和识别出的非正文页另列。识别环境不可用时，系统仍尝试读取可复制的文字，整本书没有读到可用正文时会提示失败。

### 选完文件先预检（自动识别元信息）

选文件后立刻 `POST /api/probe`，服务端边收边写盘，然后：

- PDF 预检查看封面、扉页、版权页和文件属性，尝试填入书名、作者和出版社，并提示页数和抽样页的文字情况。
- docx：读文档属性（title/author）与前 60 段；
- txt / md：读文首几行。

认出来的值直接填进表单（人改过的不覆盖）。提交时用预检返回的 `token`，
**不重传文件**。

### 大小上限

默认 **1024 MB**，用环境变量改：

```bash
BOOKDISTILL_MAX_UPLOAD_MB=2048 python3 app/run.py --port 8942
```

上传是流式落盘，内存不随文件大小涨；真正吃内存的是抽文字那一步（约为文件的 2～3 倍，
都在 runner 子进程里）。老的多段上传接口（`multipart/form-data`）保留兼容，
但它整包进内存，所以单独卡在 200 MB。

## 上传后发生什么

1. 解析文件 → 写入 `书库分类/raw/<书名>.txt`
2. `pipeline.py`：分类 / 内容切分 / 知识条目
3. `rules.py` / `topics.py` / `mirrors.py`：确认卡质检
4. `export.py` / `taglib.py`：汇总资产库 + 标签体系
5. `cardboard.py` / `board.py` / `tagboard.py`：重建静态页
6. 写入 `app/data/library.json`，任务完成

分类置信为「中 / 低」时仍自动入库，但标 **待确认**；详情页可以：
- 标为已确认
- 人工改分类（按新类型重跑知识条目与标签）

## 目录/索引页清洗与结构审计

PDF 抽取常把书前目录当成正文；目录里又会出现「第十四章 …」这种章标题，结构探测取第一次出现，就会把目录切成正文。入库流程现在有两道防线：

1. **目录清洗**（`platform/engine/tocclean.py`）：识别成块的点线/省略号目录（≥12 行），在判型与切段前剔除；无目录的书原样返回，不改一个字。清洗记录写入 `book.json` 的 `目录清洗`。
2. **结构审计**：检查正文里是否还有目录残留、章号顺序是否异常、是否有重复篇名，结果写入 `book.json` 的 `结构审计`；详情页检测到异常会直接显示红色提示，不把目录当正文展示。

全库只读体检：

```bash
python3 platform/engine/audit_structure.py
# 输出 platform/结构审计报告.md / .json
```

2026-11-10 首次全库结果：56 本中只有 B56 触发目录清洗（移除 2,922 行 / 11,512 字，章节从 `14→1→2…` 恢复为 `1→2…→14`，574 条知识条目保留）；B39 的目录在「前置」里，不进章节正文；B54/B15/B11/B27 的重复篇名是正常同名诗/条目，不是目录污染。

## 原文定位（锚点）

卡片与标签都带锚点，可以一路回查到具体某一段原文。

- 一段原文有两个编号：`id`（`B01-00-P05`）与展示用 `锚点`（`B01·前置·P05`）；
  `cards_candidate.jsonl` / `tags.json` 的「锚点」字段存的是 **`id`**。两者直接 join 会 0 命中，
  而且是静默失败——所以读侧统一走 `store.resolve_anchor()`（先按 id，再按展示锚点兜底）。
- 只改读侧，不改产物：存量 56 本不用重跑。
- 接口：`GET /api/book/segment?code=B01&anchor=B01-00-P05&radius=2`
  返回目标段 + 同篇前后各 2 段 + 篇内位置（`chapter_index/chapter_total/chapter_offset`）。
  `/api/book/cards` 与 `/api/book` 里的标签都补了 `seg_id`，前端只认这个字段。
- 前端：标签证据、知识条目卡片上都有「在原文中定位」；跳转后目标段高亮，可「取消定位」。
- 自检：`python3 app/tests/check_anchors.py`（7,761 条卡片 + 2,004 个标签锚点必须 100% 解析，约 0.5s）。
- 并发：段索引按 `mtime+size` 缓存、最多 8 本、加锁读；本机单段定位 p50 ≈ 2ms，
  40 并发混合请求约 290 req/s（瓶颈在 `/api/book` 的书详情重算，不在定位接口）。

## 两套分类，别混

- **P1–P12（类型）** 是「因果型」：判成 P11 图鉴型才会去抽物种条目，判错产物全错。所以它有置信度、拒判出口、人工改判。
- **中图法（CLC）** 是「描述型」：只决定摆哪个架子、归哪类推荐，改它不动一个字的内容。页面上标「建议」，错了改个章就行。

CLC 由 `platform/engine/clc.py` 按标题、关键词、标签给建议，写进 `out/<code>/book.json` 的 `CLC` 字段
（`代码/名称/依据/来源/置信`）。上传、恢复、改分类三条流程跑完都会自动补一次；失败不阻断入库。

```bash
python3 platform/engine/clc.py --all     # 全库回填（幂等）
python3 platform/engine/clc.py B56       # 单本
```

人工改过的（`来源=人工`）不会被重跑覆盖。要人工改：直接改 book.json 的 `CLC`，把 `来源` 写成 `人工`。

## 书码

书码是锚点前缀，跨次运行必须稳定。注册表在 `platform/library/book_codes.json`：

- 已有书保持原码（B01…B55、ZHS、MDT 等）
- 新书取全库最大 B 码 +1（B56、B57…）

## 删除 / 恢复

删除是软删除（不是彻底删除）：

- 底本 → `书库分类/退库/<书名>__<时间>.txt`
- 版面文件 → `书库分类/退库/<书名>__<时间>.layout.jsonl`
- 产物 → `platform/out/.trash/<code>__<时间>/`
- 图书索引移除，汇总库与页面重建
- 后台「回收站」可恢复；恢复会重跑流水线并重建全库

删除需要输入书名确认。规则与边界（2026-11-11 补）：

| 场景 | 行为 |
|---|---|
| 有任务在排队 / 运行中（入库、改分类、恢复） | **拒绝删除**，提示等任务结束。否则执行器会在删完后再把产物和记录写回去，书会“复活”成失败记录 |
| 重复删除（并发两次） | 只有一次成功，另一次返回「书不存在」 |
| 回收站恢复 | **先做完全部冲突检查再搬文件**：同名底本、同码产物、同码图书在库，任一命中直接拒绝，不会搬一半 |
| 同一回收站记录重复点恢复 | 只放行一个任务，其余返回 409 |
| 底本已丢失 | 恢复直接拒绝（「回收站里没有底本，只能重新上传」），不会空跑一遍流水线 |
| 删完再重传同名书 | 允许；书码复用。旧回收站记录不能恢复（会因同名底本被拒） |
| 任务记录 / 上传原件 | 不随图书删除，保留作历史与重跑依据 |

彻底删除（连备份一起清）不在这一版：回收站记录、`退库/`、`out/.trash/` 需要手工清理。

## 后台

- **解析能力**：按书型（P1–P12）× 抽取器（定义/枚举/规则/…）勾选。改动只影响之后新跑 / 重跑的书，历史产物不自动变。
- **档案**：每本书的 `book.json`、标签、catalog、操作记录；可下载 JSON。
- **查询**：跨书查书名 / 标签 / 知识条目 / 原文。
- **回收站**：查看与恢复软删除的书。

阈值（最低汉字、保留率、图谱准入等）只读展示。分类阈值不开放后台改：单本书调阈值会让全库口径失真，必须走代码 + 全库回归。
