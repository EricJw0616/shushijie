Information Architecture · 改造建议 · 2026-11-17

数据资产只做对了 2/3
应用层只兑现了 1/5

你把系统定义成「上传 → 解析 → 输出结果」，但左栏里只有前两段。输出结果（知识条目 / 实体 / 标签 / 报告）至今只能进单本书里看，没有跨书出口；应用层 5 个门，4 个点开是 alert。下面是按你的定义重排后的样子。

导航是承诺 一级入口写在那儿，客户就会点。
点进去不能干活，整页的可信度都会被折算。
宁可少一个入口，不可多一扇假门。

核心缺口：客户买的是「825 条可交付的知识条目」，不是「能点开 7 本书看 825 次」。资产必须能跨书列出、筛选、导出，才叫输出结果。

改完的效果

1
数据资产 = 三段齐全：书（容器）· 上传与解析（流水）· 资产产出（结果），一眼能读出生产链路。
2
新增「资产产出」：一行一条知识条目 / 实体 / 标签 / 报告，跨书筛选、批量导出、给应用消费。不再是书列表的复制。
3
应用组只列能点进去的：知识图谱、热点匹配。问答 / 物料 / API 不上导航，只在应用中心看接入状态。
4
全局检索降为顶栏能力，省下的一级位置给「资产产出」——入口不增反减。
5
接口与数据源 / 成员与权限要么做成真页面（接口清单现成），要么从导航删掉，不留 alert 门。
6
导航里 3 个应用有真页面可点：知识图谱、热点匹配、资产产出（今天只有 2 个）。
