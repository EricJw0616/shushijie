# 智能问答

入口：内容应用 → 智能问答（`#/qa`）。复用当前应用服务，支持选书、提问、追问、引用、原文上下文及当前浏览器的历史对话。

## 数据与检索

`qa_service.py` 读取当前有效图书清单与 `segments.jsonl`。章节、摘要、条目及标签帮助召回；提供给回答模型的证据始终是原文的连续片段。使用中文词项 BM25 排序及通用同义词扩展，当前没有启用向量数据库，不把词项检索描述为向量语义检索。

索引只驻留内存。每次状态查询或提问都核对书库及来源文件指纹；新书、重解析、退库和结构化材料修订会自动触发重建。“全部图书”以当次有效库为准，指定书目保持原范围。模型生成结束后再次检查来源版本，期间改变的结果作废，避免把旧资料作为当前答案返回。

回答复用 `platform/engine/llm.py` 的现有模型配置。生成陈述需给出来源编号与逐字支持片段，服务端检查引用、数字及原文子串，再通过单独模型调用复核支持关系。这些检查不能保证事实正确；来源观点与独立事实核查仍需区分。模型未配置、超时、引用无效或依据不足时，返回原文结果和说明，不伪造回答。外部模型会接收本次相关图书片段与有限轮次的对话上下文。

列举学习对象时优先利用已验证结构化条目的边界，检索名称所在的原文及描述，避免将相邻条目的残段拼错。`sources[].title` 仅作定位提示，不能替代原文证据。未询问药用的学习问题优先展示形态与生境。独立核验不通过的陈述会被剔除，保留的陈述仍须通过原有逐字及支持关系检查；比较问题仍须具备双方图书证据。

当前不提供全库穷尽统计或完整全书总结；仅凭有限检索结果不足以证明此类结论。当前出处定位到书、章节标记与段落，没有可靠逐页映射时不输出页码。复杂同义改写与大库召回仍是后续向量检索及评测重点。

## 接口

- `GET /api/qa/status`：有效书目及其中图分类、各分类图书数量、段落数量、模型配置状态和来源版本。
- `POST /api/qa/ask`：`question`（最多 1200 字）、`clc_code`（空字符串为全部分类，中图一级类号或 `unclassified`）、`book_codes`（空数组为当前分类全部图书）、`history`（最多最近 6 轮）。分类与指定书目取交集，空范围不回退到全库。返回 `answer`、`sources`、`suggestions`、`notice`、`scope`（包含 `clc_code`），以及 `mode`：`answer`、`sources_only` 或 `insufficient`。
- 原文上下文复用 `GET /api/book/segment?code=...&anchor=...&radius=2`。

接口沿用应用认证，最多两个问答请求并发；生成与复核分别限制超时。模型服务的原始错误正文不向用户返回。

响应的 `retryable` 指明能否通过重新生成重试；模型忙碌或生成、核验异常为 `true`，范围限制、未配置模型或证据不足为 `false`。日志仅记录失败阶段与异常类型，不记录服务商错误正文。

## 页面状态

中图分类下拉框沿用书库已有的分类信息，仅显示当前有图书的分类。选择分类后，选书列表与问答同步限定范围；未指定单书时，新入库的同类图书自动纳入。已有回答后切换分类会新建对话并保留旧对话，避免将旧范围的回答带入新范围。

“新话题”同时放在页面顶部与追问区下方，保留原对话到历史，重置问答上下文并沿用当前选书范围。前面的成功轮次默认折叠为问题摘要，最新一条可见轮次完整展开；用户主动展开的轮次在当前页面刷新渲染时保持展开。最近一个未完成问题再次提交时复用原卡片，既有成功回答不会被覆盖。

每条成功问答的底部及折叠摘要提供删除入口；页面顶部和历史对话列表可删除整段对话。删除先展示范围与目标供确认，取消不改变记录。单条删除同时移除该次问题、回答和引用，后续请求不再使用这条上下文，其他回合保持；整段删除包含全部失败记录。当前对话清空后进入新话题并沿用选书和分类。删除先成功写入浏览器存储，再提交内存与界面；存储失败保留原记录并提示重试。回答生成期间禁用删除，避免异步结果恢复已删除的内容。

对话保存在当前浏览器 localStorage，按应用地址和工作空间名称区分，最多保留最近 30 个对话；不提供跨设备同步。保存失败时保留当前页内容并提示复制。新书不会改变已指定的书目范围。历史回答保留生成时的原文快照，来源版本改变后显示提示；查看上下文读取当前原文。

样式支持窄屏布局、原文抽屉、键盘焦点与减少动态效果偏好。所有问题、模型文本和来源文字均转义后呈现。

对话采用单列阅读，引用编号和“查看依据”打开原文抽屉，避免在窄侧栏内嵌套滚动。最新一轮未完成时，显示后端说明和可回查的原文，允许修改问题，对可重试结果提供重试入口。问题会保留在输入框中。问答状态按实际可检索的段落统计，对没有可检索正文的选书提供来源入口。上下文保留已结束轮次的用户问题（含网络错误和中断请求），只有成功且非空的回答进入 assistant 历史。最近四轮之外额外保留最近一次成功问答，避免连续隐藏失败挤掉指代所需的上下文；最新轮次未成功时不展示更早回答的旧建议。页面主容器不绘制焦点外框，按钮、链接和输入控件仍保留键盘焦点提示。

问题明确提到结构化条目名称时，检索优先锁定该实体，并按分布、生境或形态选取对应字段原文。能够回答部分事实时，应给出已知范围及当前引文的限制；例如仅有“东北地区各市县”时不能编造具体城市名，也不能据此保证实地一定可见。

正文先直接回应问题，再按需要补充解释、基于原文的建议及资料边界。生成器在内部标记段落用途，所有用途仍经过相同的引用与支持关系校验；书名、章节和摘录主要留在出处中，作者观点、文学解释及来源冲突仍保留必要归属。不会用前端删句的方式改写已有回答，历史回答保持原貌。

回答采用自然交流的口吻，结合上一轮理解本次追问，只补充新问的信息；不以“资料记载”“现有材料”等组织成检索报告，也不机械添加称呼、免责声明或结尾邀聊。口语化不改变事实范围和来源要求，建议与缺口均保持准确。推荐追问使用用户可以直接发送的语气。

有依据的草稿经过一次对话表达整理，允许合并重复段落、调整表达顺序。每个草稿段落必须且只能映射到一个回复段落；回复继承对应草稿的完整引用与逐字支持片段，不能凭改写更换依据。整理后重新检查逐字引文、数字和实体，最后独立核验审核的是实际展示的文字。整理超时或格式不合法时回退草稿，继续核验；增加的一次模型调用限制为20秒，usage累计全部三个阶段。

含代词的条目追问从用户历史补足对象名称，检索字段以当前问题为准；从分布转问辨认时查询形态，明确提出的新对象覆盖旧对象，查询始终受当前分类和选书范围约束。模型在证据两端多加引号时，仅在移除这些引号后能够连续逐字命中对应原文的情况下修正；内部文字、数字和省略号均不修补，后续核验照常执行。

回答标题不重复显示引用数量；保留内联编号和底部“查看依据”。通用来源说明放在出处抽屉，实质限制及未知说明仍在正文和复制内容中保留。全库版本变化仅提示“书库已更新”，不据此断言某一引用原文已修改；该提示位于答案下方，出处抽屉另说明历史引用与当前原文的区别。

## 验证

在项目根目录运行：

```sh
./.venv/bin/python -m unittest app/tests/test_qa_service.py app/tests/test_qa_http.py app/tests/test_qa_quote_normalization.py app/tests/test_qa_conversation.py
node app/tests/test_qa_ui.mjs
node app/tests/test_route_races.mjs
node app/tests/test_workspace_navigation.mjs
node app/tests/test_material_navigation.mjs
```

服务测试使用隔离数据与模拟模型，覆盖新书入库、来源更新/退库、引用校验、证据不足、范围与追问、HTTP 请求边界及并发释放。真实模型和页面交互另作人工端到端验证。
